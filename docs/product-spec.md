# shortsmaker 제품 요구사항

출처: 2026-09-09 사용자 대화 및 제공한 쇼츠 이미지. 이 문서는 현재 요구사항 정본이다. docs/workflow.md는 검토·검증 이력을 보관한다.

## 목적과 사용 환경
사용자가 편집을 마친 롱폼을 Mac에서 불러와 주제별 쇼츠 여러 개로 만들고 Buffer를 통해 Instagram Reels와 YouTube Shorts에 예약한다.

## 기본 작업 흐름
1. 롱폼 파일 선택 및 분석. 기존 영상과 자막을 보존한다. 내용 분석용 음성 전사는 가능하지만 새 자막을 영상에 생성하지 않는다.
2. AI가 주제별 시작·끝과 분할 이유를 제안한다. 개수는 내용에 따라 결정하며 5~8개로 강제하지 않는다. 사용자는 시작·끝 조정, 추가 분할, 합치기, 제외를 할 수 있게 설계한다.
3. 각 영상 내용에서 후킹 문구 10개를 생성하고 그중 가장 좋은 1개를 AI 추천으로 표시한다. 과거 마음에 들었던 문구 제출을 전제로 하지 않는다. 추천 이유를 짧게 보여주는 것은 설계 제안이다. 사용자가 선택·직접 수정·재추천 후 확정한다.
4. 세로 화면 미리보기에서 문구와 영상 구도를 확인한다.
5. 확정된 쇼츠를 개별 파일로 일괄 인코딩한다.
6. 채널과 일정을 정해 Buffer에 예약하고 결과를 확인한다. 영상 URL은 발행 완료까지 유지한다.

## 화면 템플릿
- 검은색 9:16 세로 캔버스, 가로 롱폼을 캔버스 폭에 맞춘 상태에서 150% 확대하고 중앙 정렬하여 좌우 크롭.
- 영상에 포함된 기존 자막을 그대로 확대해 활용. 별도 자막 생성 없음.
- 상단 후킹 문구는 굵은 글씨 2줄·가운데 정렬. 흰색을 기본으로 강조할 단어·구절만 노란색으로 표시한다. 강조는 줄 단위에 고정하지 않는다. AI가 문구 후보와 강조 범위를 함께 제안하고 사용자가 변경할 수 있게 설계한다. 검은 상하 여백 유지.
- 정확한 글꼴·글자 크기·좌표는 이미지와 실제 영상 측정값으로 보정한다. 폰트 이름은 이미지로 확정하지 않는다.
- 미리보기와 출력은 동일한 배치 설정을 공유한다. 자막 잘림이 있으면 배율·위치 조정이 가능하도록 한다.

## AI 설정
- 기본 모델 Astra, 추론 강도 medium. 사용자가 모델을 선택할 수 있어야 한다.
- 모델 이름을 실제 호출 식별자로 임의 가정하지 않는다. 구현 전에 사용 가능한 연동 경로를 확인한다.

## 단계별 알림과 작업 복구
- 분석·분할 제안, 후킹 후보 생성, 인코딩, 예약 등 각 단계가 끝나면 앱에서 완료 소리를 낸다.
- 소리는 앱 작업 상태 변화에 연결하고, 화면 재접속·새로고침으로 중복 재생하지 않는 방식으로 설계한다.
- 알림 켜기/끄기, 실패 표시·재시도, 진행 상황·작업 저장은 설계 제안이다.
- 이 요구사항은 개발 중 Codex 완료 알림이 아니라 완성 앱의 알림이다.

## 이후 확장
- 작업 방식이 안정화되면 AI가 분할·후킹 선택·여러 쇼츠 인코딩까지 한 번에 진행하는 자동 모드를 추가한다.
- 현재 버전은 사용자의 구간 수정과 후킹 컨펌을 유지한다. 향후 자동 모드의 범위는 인코딩까지이며 자동 발행은 별도 결정한다.

## 검증 완료 및 남은 결정
- Buffer 실계정 두 채널의 영상 예약 생성·조회·즉시 삭제 성공. 실제 발행은 사용자 요청에 따라 시험하지 않았다.
- 실행 방식은 Mac 로컬 웹 UI로 확정. AI 호출 경로, 내용 분석용 전사 엔진, 운영 영상 저장소는 아래 제안 검토 중이다.
- 사용자 승인(2026-09-10): 주제 완결성 우선, 기본 최대3분, 초과 구간은 AI가 추가 분할 제안. 연속 구간 추출을 기본으로 한다.
- 개발 순서 제안: 샘플 분석과 화면 초안 → 로컬 미리보기·렌더 → AI 분석·분할·후킹 → 작업 상태·알림·복구 → Buffer 운영 저장소 연동.

## 2026-09-10 자동 구도 보정 검토 (설계 제안, 실증 전)
- 사용자 요청: 가로 위치를 AI가 판단해 자동으로 보정할 수 있는지 검토.
- 기술적으로 가능하다. 얼굴·인물·손·설명 대상·기존 자막 위치를 분석하고 중요 영역을 보존하는 가로 크롭을 선택하는 방식.
- 기본 150% 확대 유지. 안정적인 장면은 장면 전체에 가장 적합한 위치로 고정하고, 대상이 이동할 때만 부드럽게 추적한다. 컷 전환 시 다시 판단한다.
- 얼굴만 중앙에 놓으면 수업의 판서·손짓이 잘릴 수 있으므로, 발언 내용과 대표 프레임을 함께 보고 설명 대상을 중요 영역으로 지정하는 방식을 제안한다. 실제 시각 모델 연동·정확도는 아직 미검증.
- 기존 자막은 원본에 구워져 있으므로 가로 이동할 때 함께 움직인다. 자막 경계를 보존하는 제약이 필수이며 자막 재생성/이동은 기본 범위에 포함하지 않는다.
- 150% 배율에서 보이는 원본 가로폭은 1280/1920(약2/3)이다. 인물·판서·자막이 이 폭에 함께 들어가지 않으면 가로 이동만으로 해결할 수 없다.
- 이런 예외는 확인 필요로 표시하고 대안 구도를 제안한다. 사용자 승인(2026-09-10): 중요 내용이 잘리면 해당 장면의 배율 자동 축소를 허용한다.
- 기본 흐름 제안: 자동 보정 → 미리보기 → 필요시 수동 수정. 모델이 검출하지 못하면 마지막 안정 구도/중앙 구도로 폴백하고 확인 필요 표시.
- 검증 계획: 수업 영상의 인물·판서 동시 등장 구간, 앉아서 설명하는 구간, B-roll 전환에서 자막 잘림·주요 대상 잘림·화면 흔들림을 비교한다.
- 기술 근거: Google AutoFlip의 중요 대상 검출과 장면별 고정/팬/추적·경로 평활화. 구현 라이브러리 채택을 확정한 것은 아니다.
- 출처: https://research.google/blog/autoflip-an-open-source-framework-for-intelligent-video-reframing/ (2026-09-10 확인).

## AI 호출·영상 저장소 권고안 (사용자 확정 전)
- AI: Mac 백엔드에서 OpenAI Responses API 직접 호출. gpt-6-astra 및 reasoning.effort=medium 기본, 모델 선택 제공. 시간 정보 있는 전사와 대표 프레임을 입력하고 분할/후킹/강조 범위/구도 판단을 구조화된 결과로 받는다.
- Astra는 공식 문서상 텍스트·이미지 입력 지원, 오디오·영상 직접 입력 미지원. 내용 분석용 전사 및 프레임 추출 단계 필요. 전사 엔진은 별도 검증 후 선정하고 자막 출력은 하지 않는다.
- Codex CLI/SDK의 ChatGPT 로그인 방식도 대안. 로컬 codex-cli0.153.4와 Astra/medium 모델 캐시 확인. 그러나 API 직접 방식과 구독 방식은 과금·한도가 다르며 실제 앱 연동은 미검증.
- API 표준 단가: 입력100만 토큰당$10, 출력$50 (2026-09-10 문서 기준). 실비는 이미지·추론·재시도 포함 사용량 측정 필요. 사용자 API 계정 모델 접근은 아직 미확인.
- 저장소: Cloudflare R2 Standard + 전용 공개 미디어 서브도메인 권고. Mac 원본은 그대로 두고 예약할 최종 쇼츠만 업로드. 추측하기 어려운 객체 이름을 사용하되 URL은 공개 접근됨을 전제로 한다.
- r2.dev는 개발용이므로 운영 전달 URL은 사용자 소유 도메인 연결. 계정·도메인 보유 여부 미확인.
- 두 채널의 발행 성공 확인 후14일 보관하고 클라우드 복사본 정리 제안. 예약/오류/상태불명은 삭제하지 않음. Mac 앱 실행 시 상태 확인·정리 수행 가능. Mac 원본과 최종 로컬 출력은 자동 삭제하지 않음.
- 업로드 및 Buffer 예약 성공 후에는 Mac이 꺼져 있어도 미디어 URL 유지. 분석·인코딩·업로드와 로컬 정리는 Mac 실행 필요.
- 개발 전 순서 제안: AI 호출 경로 확정·최소 호출 → R2 계정/도메인 연결 → R2 영상 URL로 Buffer 예약·즉시삭제 재검증 → 앱 구현.
- 공식 출처: https://developers.openai.com/api/docs/models/gpt-6-astra , https://learn.chatgpt.com/docs/auth , https://developers.cloudflare.com/r2/pricing/ , https://developers.cloudflare.com/r2/buckets/public-buckets/ (2026-09-10 확인).

## AI 방식 확정 및 R2 비용 검토 (2026-09-10)
- 사용자 확정: AI는 기존 Codex 구독 로그인 방식으로 진행. 앞선 Responses API 직접 호출 권고는 채택하지 않는다. 기본 Astra medium 및 모델 선택 유지.
- R2 선택은 비용 검토 중이며 생성·결제 설정은 아직 하지 않았다.
- 실측 완성 쇼츠13개 평균41.183MB, 범위28.215~61.042MB. 보수적 계산은 개당50MB.
- R2 Standard: 월10GB-month 저장·쓰기100만·읽기1000만 요청 무료, 인터넷 전송 무료. 초과 저장$0.015/GB-month, 쓰기$4.50/100만, 읽기$0.36/100만 (단위 올림 적용).
- 50MB 영상이 한 달 내내 일정 수량 보관된 가정:100개5GB=$0,200개10GB=$0,500개25GB=$0.225(약$0.23),1000개50GB=$0.60 저장료. 요청 무료량 이내·동일 계정 다른 R2 사용 없음 가정. 도메인·세금·별도 서비스 비용 제외.
- 같은 파일 URL을 두 채널에서 사용하므로 영상 저장 용량은 두 배가 되지 않는다. 발행 확인 후 보관기간을 두고 정리하면 누적 용량을 제한할 수 있다.
- 출처: https://developers.cloudflare.com/r2/pricing/ 및 docs/reference-measurements.json의 완성본 경로 파일 크기 실측.

## 2026-09-10 R2 공개 URL 검증
- 사용자 공개 URL 입력 완료. 인증 업로드 후 공개 HTTPS GET 200 및 파일 내용 일치 확인, 테스트 객체 삭제 완료.
- Python 기본 User-Agent는 공개 요청403/Cloudflare1010을 받았으나 앱 식별 User-Agent shortsmaker-connectivity-check/1.0으로200 성공. 클라이언트 요청 식별에 따른 차이로 기록하며 Buffer 서버 접근은 별도 검증 필요.
- 앞서 승인된 테스트 영상 `5개 제대로가 10개 엉망보다 빠릅니다.mp4`가 기존 경로에 없고 Desktop 파일 검색에서도 발견되지 않아 영상 업로드·Buffer 예약은 수행하지 않았다.
