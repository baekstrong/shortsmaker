# 자동 준비 병렬 처리 검증 (2026-09-16)

## 변경
- 후킹 후보 생성과 12프레임 묶음 분석을 각각 최대 2개 요청으로 제한해 병렬 처리한다.
- 분석 단계 순서, 모델/추론 강도/프롬프트/이미지 바이트/표본 수/검증 기준은 보존한다.
- 결과는 조정 스레드에서 모아 저장하고 프레임 진행률은 완료 개수만 집계한다.
- 모든 실행 프로세스의 PID와 시작 식별자를 기록한다. 취소/오류/앱 종료 시 모두 정리하며 재시작 시 이전 형식의 단일 프로세스 기록도 복구한다.
- 실제 영상 실행의 단계별 최근 소요 시간은 작업 JSON의 `stage_seconds`에 기록한다.

## 검증
- `tests/test_parallel.py`: 최대 동시 실행 2개, 전체 결과 누락 없음, 취소/종료/실패 시 실행 프로세스 정리 및 후속 요청 차단, 재시도 성공, 재시작 시 두 프로세스 회수.
- 프레임 요청 완료 순서를 바꿔도 순차 처리와 최종 구도 결과가 동일함을 고정 AI 응답으로 확인. 프롬프트/스키마/모델/추론 강도/입력 이미지 바이트도 대조했다. 프레임 누락 응답 거부 유지.
- 기존 core/workflow/API 검증 포함 48개 통과. 실제 영상 인코딩이나 발행은 실행하지 않았다.
- 0.1초 대기의 모의 요청 8개: 순차 0.839초, 병렬 0.417초. 요청 대기 중첩 효과만 확인한 수치이며 실제 AI 속도 개선 배수가 아니다.

## 한계 및 적용
실제 AI 호출의 응답 품질과 총 실행 시간은 별도 실영상 비교 전에는 확정할 수 없다. 모델이나 검사량을 낮추는 변경은 하지 않았다. 기존 처리 중인 작업을 종료시키지 않았으며 앱 재시작 후 새 실행/재시도부터 적용된다.
