# 2026-09-11 후킹 미리보기 및 Mac 이동 호환성

## 확인한 원인과 범위

- 기존 후킹 필드는 `change` 이벤트에만 저장되어 입력창에 커서가 있는 동안 미리보기가 갱신되지 않았다. 이미지 로딩 실패를 처리하는 UI도 없었다.
- 진단 시 5099 서버는 실행 중이 아니었다. 로컬 Flask 테스트 클라이언트에서 실제 3개 프로젝트의 후킹 이미지 총 24개는 모두 HTTP 200이었다. 사용자/시스템 한글 폰트 모두 읽혔다. 따라서 스크린샷 촬영 당시 이미지 실패의 직접 원인은 확정하지 않았다.
- 0902·0825 프로젝트의 원본 크기는 동일하고 저장된 mtime은 정수 초, 현재 원본은 같은 초에 소수점이 붙어 있었다. 기존 코드는 두 원본을 거부했다. 현재 코드로 크기·길이·해상도·fps·오디오·HDR 대조 후 0908 포함 3개 원본 모두 읽기 성공했다. 원본·실제 프로젝트 JSON은 수정하지 않았다.

## 변경

- 300ms 입력 자동 저장, 한글 조합 완료 처리, 쇼츠별 미저장 입력 유지, 전환 직전 저장 대상을 고정, 즉시 확정 시 문구·강조·크기를 함께 저장한다. 문구에 없는 강조는 제거한다. 실패한 미저장 입력이 있을 때 페이지를 떠나면 브라우저가 알린다.
- 후킹 PNG를 fetch/decode 후 표시하고 이전 요청 응답의 덮어쓰기를 차단한다. 오류 설명·3초 후 자동 재시도·수동 재시도를 제공한다.
- PNG 임시 파일 작성 후 atomic replace, 캐시 무결성 검사·재생성, 실제 읽을 수 있는 한글 폰트 fallback 및 폰트 내용 해시를 렌더 키에 포함한다. 기존 영상은 삭제하지 않지만 새 렌더 키로 재인코딩이 필요하다.
- 누락된 설명 썸네일은 저장된 샘플 시각의 원본 프레임에서 재생성한다.
- 원본 수정시각 정밀도 차이만 위 조건으로 허용한다. 그 외에는 동일 원본 재연결 UI/API를 제공하며 영상 정보가 다르면 거부한다. 과거 해시가 없어 바이트 동일성은 검증하지 못한다.
- 복사된 pip 실행 파일의 과거 절대경로를 사용하지 않고 현재 Python으로 모듈 설치, 누락 모듈·FFmpeg 사전 확인을 추가했다. 비밀값과 원본의 기기 간 자동 동기화는 하지 않는다.
