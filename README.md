# Shortsmaker

편집한 가로 롱폼을 주제별 쇼츠로 만들고 Instagram·YouTube·TikTok에 예약하는 Mac 로컬 앱.

## 실행

`시작.command`를 더블클릭하면 `http://127.0.0.1:5099`가 열립니다. 터미널을 닫으면 서버가 종료됩니다.

필요 환경: Python 3.14, FFmpeg/ffprobe, Codex CLI의 ChatGPT 구독 로그인. 첫 실행 시 Python 패키지와 음성 인식 모델을 다운로드합니다. GmarketSansBold가 설치되어 있으면 사용하며 없으면 Mac 기본 한글 폰트로 표시합니다.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

## 작업 흐름

1. 편집한 가로 원본을 불러오고 **① AI 자동 준비**를 누릅니다. 주제별 연속 구간 선정 → 후킹 후보 검수 → 설명 그림·글 등장 구간 찾기를 순서대로 진행합니다. 불필요한 주제 구간은 선정에서 제외하고, 고른 쇼츠의 시작부터 끝까지 영상은 그대로 유지합니다. 전사는 분석용이며 새 자막은 넣지 않습니다.
2. **전체 영상 · 쇼츠 구간**에서 원본 전체의 장면 미리보기와 쇼츠별 썸네일을 확인합니다. 쇼츠 양끝을 드래그하면 시작·끝이 바뀌며 마우스를 놓을 때 저장됩니다. 잘못 조정하면 **되돌리기**를 누르세요. 원본 미리보기 띠나 노란 표시선을 드래그하면 쇼츠 바깥 장면도 확인할 수 있습니다.
   쇼츠를 누르면 바로 아래 **원본 컷 · 화면 구도**가 해당 쇼츠로 바뀝니다. 컷 정보가 없으면 자동으로 찾습니다. 컷 썸네일을 선택한 뒤 왼쪽·가운데·오른쪽 정렬, 확대율·가로 중심, 미리보기 드래그로 그 컷 전체의 구도를 조정합니다.
   **설명 화면 제안 · 구간별 세부 조정**을 펼치면 추천 화면·적용 시간·임의 구간 조정이 나옵니다. AI 제안은 **추천 위치 적용**을 눌러야 반영되며 수동 구도는 재분석해도 유지합니다. **쇼츠 전체 위치 편집으로**로 전체 기본값을 바꿀 수 있습니다. 포함 여부와 후킹 문구는 아래 목록에서 검토합니다.
3. **② 검토 완료 · 예약 달력**을 누릅니다. 기본은 내일부터 매일 한국 시간 낮12시에 한 편씩, 같은 쇼츠를 인스타·유튜브에 함께 발행합니다. 이 앱에 저장된 예약이 있는 날은 건너뜁니다. Buffer에서 직접 만든 예약은 자동 조회하지 않습니다.
4. 달력에서 날짜별 문구를 확인합니다. 필요하면 시작일만 바꿉니다. 채널과 YouTube 공개 범위는 접힌 설정에서 변경할 수 있으며 마지막 선택을 기억합니다.
5. **이 달력으로 확정 · 인코딩 및 예약**을 누르면 저장 폴더 선택창이 열립니다. 폴더를 선택하면 포함된 쇼츠의 문구·구도를 일괄 승인하고 인코딩 → R2 업로드 → Buffer 예약을 자동 진행합니다. 달력을 여는 것만으로 승인·예약하지 않습니다.

**인코딩만** 또는 달력의 최종 실행 버튼을 누를 때마다 저장 폴더를 선택합니다. 취소하면 시작하지 않습니다. 별도 저장 위치 사전 설정은 없습니다.

필요 없는 쇼츠는 목록의 포함 체크를 해제합니다. 선정한 구간 내부는 추가로 자르지 않습니다. 이전 버전에서 내부를 잘라 둔 다른 프로젝트에는 **기존 삭제 구간 복원**이 표시되며, **복원**으로 삭제한 부분을 되살릴 수 있습니다. 구도 적용 시간은 원본 소재를 기준으로 표시합니다.

개별 문구 확정 버튼을 모두 누를 필요는 없습니다. 최종 달력 확정이 현재 선택된 문구·구도의 일괄 승인입니다. 개별 단계만 다시 실행하거나 영상만 인코딩하려면 **개별 단계 다시 실행**을 펼칩니다.

완료된 준비 단계는 저장되며 실패/중단 후 재시도하면 이어서 처리합니다. 중단 후 편집이 바뀌었다면 개별 단계 또는 자동 준비를 새로 실행하세요. 인코딩 실패 시 예약은 시작하지 않고, 이미 예약된 항목은 중복 생성하지 않습니다. 확정 이후 날짜 충돌이나 시각 경과가 생기면 자동으로 날짜를 바꾸지 않고 다시 확인하도록 멈춥니다.

후킹은 삭제 후 남은 발언과 첫 화면을 보고 시청자의 문제·예상과 영상의 새 단서를 찾습니다. 공백·문장부호·줄바꿈 포함15~20자의 자연스러운 문장으로10개를 자유롭게 작성합니다. 처음 보는 사람도 문구만으로 상황을 이해하고, 영상에서 확인하고 싶은 구체적인 답이 남아야 합니다. 별도 AI 검수는 문구 단독 이해·궁금증·영상의 실제 답변을 각각 판정하고 세 기준을 모두 통과한 후보 중 문구 자체의 이해와 판단 대상의 명확성을 우선 비교해 추천1개를 고릅니다. 전사나 설명문으로 빠진 맥락을 보충해 통과시키거나, 조사·서술어를 빼서 짧게 만든 메모형 표현은 허용하지 않습니다. 검수에는 작성자의 표현 의도나 추천을 전달하지 않습니다. 질문형 비율이나 고정 문구 형식은 없습니다. 후보마다 접근과 검수 근거·약점을 표시하며 실제 시청 성과를 예측하는 점수는 아닙니다.

통과 후보가 부족하거나 길이·중복·강조 검증에 실패하면 한 번 보완합니다. 형식 오류가 있는 후보에는 실제 글자 수 등 구체적인 수정 지시를 전달하고, 정상 후보는 별도로 독립 검수합니다. 통과한 후보의 원문과 강조는 보존하고 약한 후보에 대한 짧은 지시만 전달해 다시 검수합니다. 같은 영상 단서를 자연스러운 여러 표현으로 전달할 수 있으며 서로 다른 사실10개를 강제하지 않습니다. 보완 후에도 형식 오류가 있는 후보는 제외하고, 형식과 독립 검수를 모두 통과한 후보만 최대10개 제안합니다. 한 개도 통과하지 못하거나 검수 응답이 잘못되면 기존 문구를 보존하고 오류를 표시합니다. 선택한 쇼츠의 후킹은 모두 검수를 마친 뒤 한 번에 저장되어 **되돌리기**로 함께 복원할 수 있습니다. 보통의 재생성은 확정한 문구를 유지하며, 현재 문구를 명시적으로 교체하면 검토 대기가 됩니다.

기본 AI는 `gpt-6-astra` / `medium`, 설정에서 변경할 수 있습니다. 음성 인식은 로컬 faster-whisper medium입니다. AI는 전사와 대표 프레임을 사용하므로 구독 사용량을 소비합니다.

## 파일과 복구

- 원본 영상은 수정하지 않습니다. 프로젝트·전사·AI 응답·렌더 캐시는 `data/projects/`에 저장됩니다. 완성본은 사용자가 필수로 선택한 저장 폴더에 복사하며, 앱의 폴더 열기는 이 폴더를 엽니다. 다른 Mac에서 폴더가 없거나 쓰기 불가하면 다시 설정해야 합니다. 기존 출력은 자동 이동·삭제하지 않습니다.
- 각 단계 완료 내용을 저장하고 앱 재시작 후 중단 작업은 재시도할 수 있습니다.
- 편집 변경 시 이전 출력은 남겨두고 새 출력만 만듭니다. 현재 내용과 다른 출력은 예약에 사용하지 않습니다.
- R2의 예약용 복사본은 선택한 모든 채널에서 발행 성공한 뒤 14일 후 정리합니다. 자동 조회는 하지 않으며 사용자가 예약 상태를 직접 새로고침할 때 확인·정리합니다.
- 예약/오류/상태 불명 영상은 자동 삭제하지 않습니다. Mac 원본·완성본은 자동 삭제하지 않습니다.
- 예약 응답이 유실되면 중복 방지를 위해 자동 재생성을 멈춥니다. Buffer에서 확인한 게시물 ID를 연결한 후 처리합니다.
- `.env.local`에 `.env.example`의 Buffer/R2 설정을 입력합니다. 비밀값과 영상은 Git에 올리지 않습니다.

## 원본 컷마다 화면 구도 고치기

위쪽 전체 영상 타임라인에서 쇼츠를 선택하면 아래에 해당 쇼츠의 원본 컷이 나옵니다. 컷 정보가 없으면 자동으로 찾으며 **원본 컷 다시 찾기**로 갱신할 수 있습니다. 원하는 컷을 누른 뒤 **왼쪽·가운데·오른쪽 정렬** 또는 확대율을 조정하면 그 컷 전체에 적용됩니다. 기존 제안을 새 컷 기준으로 다시 받으려면 **설명 화면 찾기**를 실행하세요. AI 제안은 직접 적용하기 전까지 영상 구도를 바꾸지 않습니다.

쇼츠 길이를 줄이면 남은 컷과 수동 경계를 보존하고, 늘리면 추가된 영상까지 컷을 다시 찾습니다. 자동 컷 갱신 후에도 **되돌리기** 한 번으로 길이 변경을 취소합니다.

**−1 프레임 / +1 프레임**으로 전환 직전·직후를 확인하고, 선택 컷의 시작·끝을 한 프레임씩 옮기거나 현재 프레임에 맞출 수 있습니다. 누락된 전환에는 **현재 프레임에 컷 경계 추가**, 불필요한 경계에는 **선택 컷과 다음 컷 합치기**를 사용합니다. 타임라인에 초점을 두면 좌우 방향키는 프레임, 위아래 방향키는 컷 이동입니다. 이 작업은 구도 편집 범위만 바꾸며 영상 내용을 삭제하지 않습니다. 잘못 수정하면 **되돌리기**로 복구하세요.

## 개발 검증

```sh
.venv/bin/python -m pytest -q
node --check static/app.js
node tests/test_cut_editor.cjs
```

초기 검증은 `docs/verification/initial-version.md`, 자동 진행·달력 검증은 `docs/verification/automatic-calendar.md`에 기록합니다. 개인 실사용 베타 구현 및 두 원본16개 쇼츠 검증을 완료했습니다. 실제 플랫폼 발행 시험은 하지 않았습니다.

## 다른 Mac으로 옮길 때

- 앱 코드 외에 `data/`와 원본 영상도 함께 옮겨야 기존 편집이 열립니다. `.venv`는 기기마다 새로 만드는 것을 권장합니다. 실행기는 빠진 Python 모듈을 확인하고 현재 Python의 `-m pip`로 설치하며, FFmpeg 누락을 안내합니다. `.env.local`과 Codex 로그인은 해당 Mac에서 준비합니다.
- 원본 경로가 달라졌으면 미리보기 아래 **원본 다시 연결**에서 같은 원본을 선택합니다. 크기·길이·해상도·fps·오디오·HDR 정보를 대조하고 기존 구간·후킹·구도를 유지합니다. 이 대조는 파일 전체의 바이트 동일성을 보증하지 않으므로 다른 내용의 영상을 선택하지 마세요.
- 예전 데이터의 수정시각이 정수 초로 저장됐고 현재 파일과 같은 초·크기·영상 정보인 경우에는 소수점 정밀도 차이를 허용합니다. 그 밖의 파일 변경은 자동 허용하지 않습니다.
- 후킹 문구·강조·크기는 입력을 0.3초 멈추면 자동 저장·미리보기 반영됩니다. 서버 연결 실패 시 입력은 화면에 남습니다. 서버를 다시 실행하고 **이 문구로 확정**을 누르면 다시 저장할 수 있습니다.
- 후킹 이미지 오류는 원인을 표시하고 자동 재시도합니다. 손상된 PNG와 누락된 설명 썸네일은 다시 생성합니다. 폰트 파일이 손상됐으면 다음 한글 폰트를 사용하며, 실제 폰트가 달라지면 기존 렌더 캐시를 재사용하지 않습니다. 기존 완성 영상은 보존되며 새 편집·폰트 반영은 재인코딩해야 합니다.
- `시작.command`의 터미널을 닫으면 서버도 종료됩니다. `Failed to fetch` 대신 서버 재실행 안내가 표시됩니다.

### 실행 명령이 터미널에서 깨져 보일 때

`/User/Users/...commandit; exitit;`처럼 표시되면 앱 서버가 실행됐는지 먼저 확인합니다. 서버 실행 후 브라우저 주소는 `http://127.0.0.1:5099`입니다. 터미널의 깨진 입력은 Control+C로 취소하고 아래 명령을 한 줄로 붙여넣어 실행할 수 있습니다.

```sh
/bin/zsh "/Users/baek/Desktop/앱 제작/22. 쇼츠 편집기/시작.command"
```

현재 프로젝트 폴더 위치에 맞는 경로를 사용하세요. 실행기는 환경 확인·서버 시작 상태를 표시합니다. 모듈 존재 여부만 검사하여 음성 인식·영상 라이브러리를 시작 단계에서 함께 로딩하지 않습니다.
